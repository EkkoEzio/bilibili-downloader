# bilibili download

本地网页应用,把 B 站视频高画质留存到本地。支持大会员 1080P+/4K。

> **v2.1.0**:下载文件名对齐官方标题 · 任务史原子持久化 · 登出无残留 ·
> 前端页控制器模块化 · 后端拆 taskstore/parsing/files/bilibili_api ·
> `BD_PORT` 可换端口。详见 [CHANGELOG.md](CHANGELOG.md)。

## 快速开始

1. **双击 `启动.command`**(首次会自动建 `.venv` 并装依赖;若上次实例
   还在运行,会先自动关闭再启动新代码——避免「改了不生效」)
2. 浏览器自动打开 `http://localhost:5050`(若没自动打开,手动访问)
3. **左下角点账号**扫码登录 → 顶部分页浏览或「新建下载」粘贴链接;
   已下过的视频出现在「下载记录」页(队列进度也在这里)

## 环境要求

- macOS(已在 Apple Silicon 测试);理论上 Linux/Windows 也能跑(ffmpeg 路径自适配)
- ffmpeg(下载引擎依赖):`brew install ffmpeg`
- Python 3.10+(首次启动自动建 `.venv` + 装 yt-dlp / flask / qrcode / pillow)

## 三种登录方式

左下角**账号入口**:上半部分是登录,下半部分是全部设置(改动即生效)。

| 方式 | 说明 |
|---|---|
| **扫码登录**(推荐) | 本地 `qrcode` 库生成二维码,手机 B 站 App 扫码确认,长期有效 |
| **使用 Edge** | 读 Edge 浏览器已有的 B 站登录态(`--cookiesfrom-browser edge`) |
| **cookies.txt**(兜底) | 浏览器扩展「Get cookies.txt」导出后粘贴 |

> 不做账号密码+极验滑块(B 站限制,无法自动化)。

## 功能一览

### 左侧导航(六页)

按顺序:**下载记录 → 观看历史 → 关注动态 → 追更合集 → 我的收藏 → 稍后再看**。
每个列表页工具栏一致:**搜索 / 刷新 / 切换列表/网格视图**。
刷新语义统一:立即展示已有数据 + 后台取新(永不阻塞)。

#### 下载记录(队列已并入)

- 进行中任务排最前:**进度条 / 速度 / 剩余时间 / 取消**,SSE 实时就地更新卡片;
- 后面是已完成 / 失败 / 取消的记录,失败任务显示原因;
- 侧边栏角标显示进行中数;
- 勾选任意条目 → 底部「删除记录 / 删除记录 + 文件」(按选中删);
  页头「清除记录」弹窗里有「只清失败 / 失效」选项;
- 完成卡片右下角**播放按钮**:在 Finder 中定位该视频的文件
  (按 UP 归档也能找到)。

#### 观看历史

- 自动加载,含观看进度百分比;
- 滚动到底自动逐页加载更早的历史(B 站接口分页);

#### 关注动态

页头分段切三个视图:

- **关注动态**(B 站关注 UP 的最近投稿,5 分钟缓存,串行防风控);
- **关注列表**(我关注的所有 UP,一键加入清单);
- **自动下载**(本地清单 UP 名单,直接在页面管理:粘贴链接添加、
  逐 UP 配默认清晰度、移除、立即检查);

#### 追更合集

- B 站上追的合集(从官方 `collected/list` 接口接入,实测踩到「必须 `platform=web`」
  这个必带参数坑);
- 卡片 / 列表两种视图,按合集名搜索;
- 点进去看视频、批量下载。

#### 我的收藏

- 收藏夹列表,卡片 / 列表两种视图,按收藏夹名搜索;
- 进入看内容、批量下载。

#### 稍后再看

- 待看清单,批量下载。

### 「秒开不干等」机制

打开任一列表页都是这个流程:

1. 立即渲染 `data/cache/<key>.json` 的上次数据(不显示加载圈);
2. 后台请求真接口;
3. 拉到与展示的不一样时,顶部提示「**获取到新内容 · 查看最新**」,你点了才换;
4. 数据没变就什么都不打扰。

无缓存的冷启动才显示加载态。所有缓存键有白名单,避免任意文件读写。

### 下载

- **单视频解析**:粘贴链接 → 选清晰度 → 下载(2160P 4K / 1080P / 720P / 480P / 360P)
- **分集(多P)视频**:自动识别 → 选单集或一键多选
- **批量下载**:多链接一次粘贴 / 收藏夹 / 合集 / UP 清单批量
- **DASH 高画质**:自动合并音视频(ffmpeg),输出单个 mp4
- **仅音频**:清晰度下拉选「仅音频」,只下音轨(m4a),不合并视频
- **就近降档**:选了某清晰度但源没有时,自动降到不超过该档的最高画质
- **失败自动重试**:最多 3 次,带递增退避;取消的任务立即退出

### UP 清单:加入即自动下载

- 「关注动态 → 自动下载」视图管理:粘贴 UP 主页链接/mid 添加;
  关注列表视图也可一键「加入清单」
- **加入清单 = 自动下载**:该 UP 的新投稿由后台按设置间隔
  (默认 30 分钟,下限 10 分钟)串行检查,**直接进下载队列**(单并发串行)
- 每个 UP 单独配默认清晰度(最高画质自动/1080P/720P/480P/360P/仅音频)
- **添加时以当前最新投稿为基线**,只下载加入之后的新投稿,
  不会翻旧账批量补档
- 也可点「立即检查新视频」手动触发一轮
- 限流时不推进「已见」标记,下一轮重试,不漏视频
- ⚠ 自动检查是协议「自动程序」条款场景,故间隔刻意保守
  (≥5 秒/UP),详见 `docs/COMPLIANCE.md`

### 设置(账号抽屉下半部分)

按「下载 / 自动下载 / 保存内容 / 外观」四组排列;**改动即生效**,无需点保存,
标题旁闪「**已自动保存**」轻提示。配置项:

| 分组 | 项 |
|---|---|
| 下载 | 下载目录 / 同时下载数(1-4) / 单任务限速 |
| 自动下载 | 检查间隔 |
| 保存内容 | 弹幕 / 字幕 / 封面 / 按 UP 建子目录 / 完成通知 |
| 外观 | 主题(浅色 / 深色 / 跟随系统) |

所有设置持久化到 `data/config.json`,重启仍在。

## 常见问题

**Q: 改了代码不生效?**
A: 双击 `启动.command` 重启——新版启动器会**自动 kill 旧实例**再启动新代码,
避免旧进程占着 5050 端口。

**Q: 下载时提示「该清晰度需大会员」或只给低画质?**
A: 没带登录态或没大会员。扫码登录或切换 Edge 模式,确认账号是大会员。

**Q: 登录突然失效?**
A: B 站 cookie 会过期。重新扫一次码,或重新点「使用 Edge 登录态」刷新。

**Q: 扫码一直「等待扫码」?**
A: 二维码有效期约 3 分钟,过期后重新点「显示二维码」生成新的。

**Q: 端口 5050 被占用?**
A: 改 `config.py` 里的 `PORT`(默认避开 macOS ControlCenter 的 5000)。
启动器启动前会自动 kill 占端口的旧实例,基本不会冲突。

**Q: 关注更新 / 收藏夹只返回少量项?**
A: B 站对 `arc/search` 接口有限流,密集调用会触发;等几分钟再刷新即可。
带平台参数(我们已设好)。

**Q: 想换下载目录?**
A: 设置 → 改下载目录 → 失焦即生效。后续所有下载保存到新目录。

**Q: 想暂停后台下载,不想占浏览器?**
A: 当前需要保持浏览器 tab 开着。不打包成桌面应用(见 `docs/BACKLOG.md` 决策)。

**Q: 这个工具合法吗?**
A: 个人自用、只下载自己账号有权观看的免费内容、不外传,法律风险低;
但违反 B 站用户协议,可能限流/封号。**不要**用来下付费/大会员内容,
也不要把下载内容再传播。详细分析见 `docs/COMPLIANCE.md`。

## 项目结构

```
├── app.py              # Flask 路由层(薄;@api_errors 统一异常出口)
├── bilibili_auth.py    # 登录与会话:扫码/Edge/cookie + cookiejar 缓存
├── bilibili_api.py     # B 站读接口客户端(历史/收藏/合集/关注/UP 投稿)
├── downloader.py       # 下载执行引擎(线程/重试/进度/取消/通知)
├── taskstore.py        # 任务状态表 + tasks.json 原子持久化 + 统计
├── parsing.py          # yt-dlp 解析(单视频/多 P/收藏夹合集列表)
├── files.py            # 落盘文件名组装/对齐/改名冲突处理
├── quality.py          # 清晰度标注与 format 归一化(纯函数)
├── config.py           # 运行时配置(字段表驱动;BD_PORT 可换端口)
├── up_list.py          # 自定义 UP 清单数据层(per-UP 默认清晰度)
├── auto_refresh.py     # 自动下载轮询(串行防风控,新投稿直接入队)
├── pagecache.py        # 页面数据缓存(打开秒显上次数据)
├── storage.py          # 统一 JSON 持久化(原子写 + 损坏备份)
├── extras.py           # 弹幕抓取(protobuf)+ bvid 提取 + 文件名清洗
├── templates/index.html# 单页前端骨架(结构与内联事件)
├── static/js/          # 前端 ES modules:
│   ├── app.js          # 入口 + window 桥(内联 onclick 兼容)
│   ├── lib.js          # 页控制器框架(共享状态/无限滚/操作条/缓存优先)
│   ├── pages/*.js      # 六页各一控制器(下载/历史/动态/合集/收藏/稍后再看)
│   └── *.js            # util/icons/net/theme/quality/login/settings/drawer/newdl
├── tests/              # 单元测试(161 个)
├── data/               # 运行时数据(gitignore)
│   ├── config.json     用户设置
│   ├── tasks.json      下载任务历史
│   ├── up_list.json    UP 清单 + 已见标记
│   ├── cache/          各数据源上次结果(打开秒显)
│   ├── sess.json       扫码登录缓存
│   └── cookies.txt     cookies.txt 导入
├── 启动.command         Mac 双击启动(首次装依赖,启动前自动 kill 旧实例)
├── CHANGELOG.md        ← 版本变更日志
├── docs/
│   ├── REQUIREMENTS.md ← 完整需求文档(代码实际状态)
│   ├── BACKLOG.md      ← 产品待办 + 历史批次记录
│   ├── COMPLIANCE.md   ← 法律风险边界与合规护栏
│   └── superpowers/    设计文档 + 实现计划
└── requirements.txt    yt-dlp / flask / requests / qrcode / pillow
```

## 数据隐私

所有数据(登录态 / 任务 / UP 清单 / 设置 / 缓存)全部存在本地 `data/` 目录,
**不上传任何服务器**。扫码二维码走的是 B 站官方接口;Edge 模式只读本机浏览器 cookie。
