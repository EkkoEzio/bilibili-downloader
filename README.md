# bilibili download

本地网页应用，用于在用户确认拥有授权的前提下，把 B 站视频保存到本地。支持登录态下可访问的高清格式、批量任务、自动追更和本地任务管理。

> **v2.3.0**：本版新增稳定任务/产物身份、安全持久化与删除、认证指纹/生命期/代际隔离、聚合任务事件流、严格 API 错误、容量保护、单实例锁及前端异步/无障碍改进，并统一收藏夹与追更合集的空封面表现。发布详情见 [CHANGELOG.md](CHANGELOG.md)。

## 快速开始

1. 双击 `启动.command`。首次运行会创建 `.venv` 并安装 `requirements.txt` 中的依赖。
2. 启动器遵循 `BD_PORT`（默认 `5050`），先取得工作区单实例锁；若已有本项目实例或目标端口被未知进程占用，只报告原因并退出，不会终止未知进程。
3. 服务确认 ready 后才打开浏览器。若未自动打开，访问 `http://localhost:<端口>`。
4. 左下角点「账号」选择登录方式；随后可浏览内容或在「新建下载」中粘贴链接。

终端中使用其他端口：

```bash
BD_PORT=5051 ./启动.command
```

同一工作区一次只允许一个实例；换端口不会绕过该限制。启动器不保存服务 PID，也不创建 pidfile 或向进程发送信号：它启动一个以单调时钟 deadline 严格限制为 60 秒、只负责探测 ready 并打开浏览器的辅助进程，且每次网络超时、重试休眠和打开等待都受剩余时间约束；随后用 `exec` 原位进入 `app.py`，因此终端信号和最终退出码直接属于 Python。ready 超时只提示，不会自动停止仍在启动中的服务；需要停止时请在服务终端按 `Ctrl-C` 或正常关闭该终端。下载和自动追更都由后端进程执行，登录完成后浏览器 tab 可以关闭，之后重新打开页面即可继续查看进度；服务终端仍需保持运行。

## 环境要求

- Python 3.10+
- ffmpeg（音视频合并需要）
- macOS 已测试；核心代码兼容 Linux/Windows，双击启动器和通知能力按平台有所不同

## 登录与认证隔离

| 方式 | 说明 |
|---|---|
| **扫码登录**（推荐） | 本地生成 B 站官方登录二维码，手机 B 站 App 扫码确认。二维码与登录 Cookie 都可能过期；有效期由 B 站返回状态决定，本项目不承诺长期有效。 |
| **使用 Edge** | 读取 Edge 中已有的 B 站登录态（`--cookiesfrom-browser edge`）。 |
| **cookies.txt** | 导入包含 `SESSDATA` 的 Netscape cookies 文件。 |

不提供账号密码与滑块验证码自动化。

认证状态由随机 `incarnation`（生命期）和生命期内单调推进的 `generation` 共同标识；来源或账号变化会在当前生命期内推进 generation，缺失、损坏或不可恢复的认证状态则开启全新 incarnation：

- 后端请求绑定一致的认证快照，避免“旧 Cookie + 新账号状态”混用；
- 账号由非敏感指纹标识，Cookie 不写入页面缓存路径或 API 响应；
- 内存缓存和磁盘缓存都按 `source + account fingerprint + incarnation + generation` 隔离；
- 合法 v1 认证状态迁移到 v2 时保留原有来源、指纹、generation 与认证标志，但分配新 incarnation，因此不会认领旧缓存；
- 状态缺失、损坏或凭据不可恢复时生成新 incarnation，generation 从该生命期重新开始，旧生命期缓存不回退复用；
- 慢请求返回时若认证已变化，接口返回 `auth_context_changed`，不会把旧账号结果提交给新账号；
- 前端登录状态刷新使用独立 sequence + AbortController；退出、来源切换、Cookie 导入和可能保存会话的扫码 poll 另共享单调 mutation owner，在响应后、状态刷新后以及提示或二维码清理前重复校验。后开始的认证操作会淘汰迟到流程，旧 200/409、catch 和 finally 也不能覆盖新 UI 或重复发出 `auth:changed`；
- 退出或切换登录来源会清相关内存缓存，但不会借此清除 B 站风控冷却。

扫码页面只有在后端轮询到成功并保存凭据前需要保持打开。凭据保存成功后，关闭浏览器不会取消下载或后台追更。

## 功能概览

### 六个一级页面

侧边栏顺序：**下载记录 → 观看历史 → 关注动态 → 追更合集 → 我的收藏 → 稍后再看**。

- **下载记录**：进行中任务置顶；显示进度、速度、剩余时间、取消、失败原因、文件定位和记录清理。
- **观看历史**：显示观看进度，滚动加载更早记录，可多选下载。
- **关注动态**：包含关注投稿、关注列表和本地自动下载清单三个视图。
- **追更合集 / 我的收藏 / 稍后再看**：支持搜索、列表/网格切换、进入内容和批量下载。

动态文本统一转义；外部 URL 只接受 HTTP(S)，数字字段按规范类型处理。

### 认证命名空间缓存

除观看历史外，常用列表页会先显示当前账号、incarnation 与 generation 的本地缓存，再在后台拉取新数据。生产缓存路径形如：

```text
data/cache/accounts/<account-fingerprint>/i-<incarnation>/g-<generation>/<key>.json
```

缓存不会跨账号、跨认证生命期或跨代际回退复用。关注动态、关注列表等慢源在数据变化时提示「获取到新内容 · 查看最新」；追更合集、收藏夹、稍后再看等快源在没有选择中的项目时可无感替换。超过 30 天未更新的页面缓存会在启动时清理。

### 下载

- 单视频解析：选择 2160P / 1080P / 720P / 480P / 360P 或仅音频；实际可用格式取决于账号权限与上游返回。
- 多 P：识别分集、选择具体 P 或批量下载。
- 批量：支持多链接、收藏夹、合集等入口；单次输入和展开结果最多 100 项。
- DASH：通过 ffmpeg 合并音视频；缺少所选清晰度时就近降档。
- 可选保存字幕、封面、弹幕，并可按 UP 建子目录。
- 失败自动重试，用户取消后不继续重试。

所有单任务、批量和自动追更共用后端下载队列与运行时并发 gate。浏览器 SSE 只负责观察状态，断开页面不会停止 worker。

### 稳定任务与产物身份

- 每条任务使用稳定 `task_id`；每组媒体及副文件使用独立 `artifact_set_id`。
- 新任务从创建起带固定下载根和产物 manifest；完成后 manifest 记录已确认的主媒体与白名单副文件。
- `actual_filename` 仅用于展示和旧数据兼容，新任务的文件操作以 manifest 为事实源。
- 创建任务时先原子写入 `tasks.json`，成功后才让任务在内存可见并进入运行队列；这里是应用层 durable-first，不等同于断电级 `fsync` 保证。
- 取消操作先把候选 `cancelling` 快照写入 `tasks.json`，成功后才向 worker 发布 `status="cancelling"` 与 `cancel=True`；写失败时内存取消不可见。若写盘期间任务已经终结或被替换，会以当前任务表校正磁盘，不把旧任务复活。
- 删除活动任务时先持久化取消意图并等待对应 worker 静默；随后先持久化“已移除记录”的新快照，再删除已确认属于该任务的文件。无法证明归属、等待超时或文件删除失败时会保留/报告部分结果，不静默扩大删除范围。
- 历史任务继续使用保守兼容路径；存在多个候选文件时拒绝破坏性删除。

### 自动下载清单

- 添加 UP 时以当前最新投稿为基线，只处理之后的新投稿。
- 每个 UP 可配置默认清晰度。
- 手动与定时检查共享同一个非阻塞原子预约；只有预约成功才报告已启动，同一时刻的重复触发直接跳过、不排队，也不改写上一轮状态。
- 预约一直持有到本轮成功或错误终态状态写完，避免两轮生命周期状态交错。
- 使用“时间戳 + 同秒 BVID 集合”游标；单轮最多扫描 3 页，未跨过旧游标时保存续扫状态。首页漂移后同时推进 deep 前沿并持久修复低页接缝；即使 deep 已找到末页/旧游标，也要等 `head_repair_until_pn` 连续闭合后才提交新游标，避免跨轮永久漏页。
- 自动任务失败或重启中断后按持久任务史做指数退避恢复。

## 请求治理与本机安全

- 本项目自己发出的 `requests` / B 站 API 调用经过共享 governor：单进程最多 2 个直接 HTTP 调用在途，并按类别控制间隔及 412/429 冷却。
- yt-dlp 每次解析/下载尝试开始前会等待 governor 的媒体间隔与冷却，但 **yt-dlp 内部发出的所有 HTTP 请求并不占这两个槽，也不保证逐请求经过 governor**。下载并发另由全局下载 gate 控制。
- 自动追更额外维持 UP 间至少 5 秒、轮询至少 10 分钟。
- Web 服务只接受 `localhost`、`127.0.0.1` 或 `[::1]`；浏览器来源头存在时必须严格同源。
- API 错误使用稳定的 `{ok:false,error,code}` 结构；API 响应禁止缓存，未知异常不回显内部堆栈。
- 下载页使用一个聚合任务 SSE；旧的单任务 SSE 暂作兼容。两者共享单进程 16 条连接容量，满载时明确返回 503。

## 容量边界

| 资源 | 上限 | 行为 |
|---|---:|---|
| 单次批量输入 / 播放列表展开 | 100 | 超限整批拒绝或要求分批处理 |
| 自动下载 UP 清单 | 100 | 超限拒绝新增 |
| 单 UP 持久续扫项目 | 500 | 超限明确失败，不裁掉旧项后推进游标 |
| 等待队列（`queued`） | 500 | 新批次整批拒绝 |
| 任务历史 | 10,000 | 新批次整批拒绝；启动加载超限时保留原文件并退出 |
| `tasks.json` 启动读取 | 64 MiB | 超限保留原文件并明确退出；不是写入前大小预检 |
| SSE 连接 | 16 | 聚合与兼容单任务流共享、按单进程计算 |

## 设置

账号抽屉下半部分按「下载 / 自动下载 / 保存内容 / 外观」分组，改动即保存：

- 下载目录、同时下载数（1–4）、单任务限速；
- 自动检查间隔；
- 弹幕、字幕、封面、按 UP 归档、完成通知；
- 浅色、深色、跟随系统。

配置写入 `data/config.json`。日志写入 `data/app.log`，按约 5 MiB 轮转并保留 3 个备份，同时输出到终端。

## 常见问题

**改了代码但页面还是旧的？**

先在原终端正常停止旧实例，再重新运行。工作区单实例锁会拒绝第二实例，不会通过终止端口占用者来“抢”端口。

**端口被占用？**

使用 `BD_PORT` 选择其他端口。若目标端口由未知进程占用，启动器只报告并退出；请自行确认进程归属，不要直接强制终止。

**扫码一直等待或提示过期？**

二维码状态由 B 站决定。确认手机已完成授权；收到过期状态后重新生成二维码。不要把任意固定时长视为本项目保证。

**关掉浏览器会停止下载吗？**

不会。下载与自动追更运行在后端进程中；只要服务终端仍在运行，稍后重新打开页面即可查看。扫码登录尚未被后端确认保存时例外，请先等待页面显示登录成功。

**高画质不可用？**

确认登录态、账号权限和源视频是否提供该格式。工具不会绕过 DRM、付费墙或平台权限判断。

**请求过于频繁？**

明确 412/429 会触发冷却；冷却期内直接 HTTP 调用快速返回 429。yt-dlp 内部请求不在两槽 governor 的逐请求保证内，仍应避免高并发和频繁重试。

## 数据、网络与隐私

登录凭据、任务、设置、UP 清单和页面缓存持久化在本机 `data/`。为了登录、浏览、解析和下载，应用会把必要的请求及认证 Cookie 发送给 B 站或由 yt-dlp 访问相应媒体地址；“本地存储”不等于“完全不与 B 站通信”。本项目不设自己的远端账号或遥测服务，也不应把 Cookie、任务文件或缓存上传给无关第三方。
