# UI 统一改版设计(2026-08-17)

## 背景

用户反馈旧界面"丑、AI 味重、各页面不一致、右边大片留白"。具体问题:

1. `.main` 限宽 940px 且不居中,宽屏右侧大面积空白
2. 5 个列表页各自重复一整套工具栏/批量操作栏,位置和样式有细微差异
3. 登录区、UP 清单管理、设置等低频功能摊在页面主体里,层级混乱
4. 视觉噪音:卡片阴影堆叠、状态标签整块彩色底、按钮体系不统一

## 用户确认的方向

- 保留左侧边栏,主内容区加宽(1120px 居中)
- 登录 / UP 清单管理 / 设置全部收进右侧抽屉

## 布局骨架

- 侧边栏 200px:5 个内容页导航(下载记录 / 观看历史 / UP 更新 / 收藏夹 / 稍后再看)
- 旧的「关注账号」和「更新推送」两页合并为「UP 更新」,页头分段切换数据源:我的清单(/api/up-updates)/ 站点关注(/api/follow-updates),选择记忆到 localStorage
- 侧边栏底部固定入口:账号(登录状态圆点)、设置、主题切换
- 每个列表页页头结构完全一致:左标题,右 [页面专属按钮] + 搜索框 + 刷新 + 视图切换
- 列表默认网格视图(auto-fill minmax(200px,1fr)),封面 16:9 + 时长角标 + 观看进度条
- 勾选视频后底部弹出固定操作条(全选/取消/清晰度/下载选中),替代各页面内嵌操作栏

## 抽屉系统

右侧 420px 滑入抽屉 + 半透明遮罩,Esc/遮罩/× 关闭。三个面板:

- **账号**:登录状态卡 + 扫码/Edge/cookies 三个标签页(已登录时隐藏登录表单)
- **UP 清单**:添加输入框 + UP 列表(头像/追更开关/移除)+ 查看本地历史/刷新入口
- **设置**:全部原设置项,set-row 行式布局

## 视觉降噪

- 面板改为 1px 边框平面卡片,去掉多层阴影
- 按钮四级体系:primary(实心)/ ghost(描边)/ danger(红描边)/ quiet(无边框)
- 任务状态标签改为色点 + 文字,不再整块底色
- 深浅两套主题用 CSS 变量统一,语义色(绿/红/琥珀)各带半透明背景变体

## 不改变的部分

- 全部后端 API 与 JS 业务逻辑(parse/batch/SSE 进度/追更/已下载角标等)
- 收藏夹文件夹浏览保留在页面内(属于浏览流,非低频功能)

## 第二轮修正(用户反馈后)

1. **网格真自适应**:内容区 max-width 提到 1560px(下载页单独限 1120px),网格列数随宽度变化;分页每页条数按 `列数×4` 保证每页整数行不留空(内容不足一页时全显示)。列数由 CSS auto-fill 规则反推(`floor((宽+gap)/(200+gap))`),不量 DOM——量已渲染卡片会被上一个视图的布局污染(列表视图的整行宽卡片会把列数算成 1)
2. **列表视图**:改为左勾选+150px 缩略图+右侧标题/元信息/进度条的横排结构(原来是图上文下)
3. **收藏夹 bug**:内容接口原来用 yt-dlp 解析 medialist 且传错 id(fid 而非长 id),风控时静默返回空;改为原生 `/x/v3/fav/resource/list` + 正确 media_id,翻页 0.3s 间隔,错误透传不再吞
4. **关注列表**:`UP 更新` 页分段扩展为三源(我的清单/关注动态/关注列表);新增 `/api/followings`(全量关注 UP,10 分钟缓存)和 `fetch_followings_all`;关注列表每卡可一键加入本地清单(复用 `/api/up-list/add`)
5. **请求竞态防护**:切换数据源时,旧请求返回后不再覆盖当前视图(meta/list 均加源校验)

## 第三轮修正(用户反馈后)

1. **列表视图条数可选**:网格保持 auto(列数×4 整行),列表视图在分页器里提供 20/30/50/100 条/页选择,偏好存 localStorage(`bd_list_size`)
2. **下载记录页改视频网格**:主页面像观看历史一样展示已完成下载(封面/标题/UP/时长,按完成时间倒序,可搜索/切视图/分页);「新建下载」和「下载队列」收进右侧抽屉;页头保留统计(总条数/总大小/本月/今日)和队列角标(进行中任务数)
3. 任务记录补充 `thumbnail/uploader/duration/created_at` 字段(downloader.py):单视频创建时直接写入,批量由前端透传列表项元数据,兜底在 `_run_download` 解析后回填;存量旧任务无封面时卡片显示占位底色
4. 下载记录页隐藏勾选框(都是已下载,批量操作条不生效);空状态文案单独处理

## 第四轮修正(用户反馈后)

1. **观看历史改无限流**:删掉客户端分页和「加载更早」按钮,滚到距底部 600px 自动追加下一批(搜索中不触发);其他列表页保留分页+条数选择
2. **追更检查与下载分离**:后台线程发现新视频只写入「待确认」列表(up_list.pending,上限 200),不再自动入队;侧边栏「UP 更新」显示数量角标,页面顶部横幅「追更发现 N 个新视频 [全部下载/忽略]」,点下载才入队(单并发)
3. **追更页缓存秒开**:进入先渲染本地 /api/up-history,后台串行检查(include_seen)完成后静默替换;不再让用户盯着转圈
4. **风控参数**:UP 间隔 3s→5s,全量页大小 20→15;限流不推进 last_seen 的语义保留(不丢数据)
5. 30 秒轮询顺带刷新追更角标;设置/README 文案同步为"确认后下载"

## 第五轮修正(用户反馈后)

1. **源地址跳转**:所有视频卡片标题链到 B 站视频页、UP 名链到空间页(新标签打开);后端各 fetcher 补 `uploader_mid`(history/toview/fav/arc-search)。不做自建播放器:B 站 DASH 流需 WBI 签名+cookie 且链接时效短,自建播放器等于重做一套下载解密,外链是更稳的选择
2. **关注动态无限滚**:该源一次性合并前 30 个关注 UP 的近期投稿,改为全量渲染、去掉分页器和页码文案
3. **关注列表无限滚**:去掉分页,渐进显示(网格首屏 24/列表 30),滚到底追加;文案改"共关注 91 个 UP · 已显示 X"
4. **关注列表视图切换修复**:原来 up-grid 写死导致切换无效;现网格=.up-grid 卡片阵、列表=.up-list 整行卡片,切换时重算首屏条数

## 第六轮修正(用户反馈后)

1. **滚动模型重构**:整页滚动改为内容区独立滚动(.main 固定 100vh,.content overflow-y:auto),页头 position:sticky 吸顶——无限滚动时搜索/按钮始终可用,不用滚回顶部
2. **回顶按钮**:右下角浮动按钮,内容区滚过 500px 显示,点击平滑回顶
3. **首屏填满**:computePageSize 增加高度维度(行数=视口高/行高),视频卡行高约 232、UP 行卡约 76;关注列表网格首屏从 24 提升到铺满(1000px 高约 55)
4. **UP 更新零加载态**:我的清单/关注动态进入时只渲染本地缓存(内存/up-history),后台静默串行检查,成功才替换;失败/限流保持现状,不再整页转圈或空白
5. **无限流页面去掉进度噪音文案**:历史/关注动态/关注列表的 meta 不再显示"已加载/已显示 X",仅搜索时显示匹配数

## 第七轮修正(用户反馈后)

1. **页头完全固定**:sticky top:0 从第一像素就不动,加高(18/14 padding)+ 底边线,滚动时像稳定的工具栏
2. **交互全面统一**:所有列表页(下载记录/历史/UP 更新三个源/收藏夹/稍后再看)统一无限滚动,删除全部页码分页器和条数选择器;滚到底先追加本地块,历史页本地用完再向服务器要更早的
3. **按钮规格统一**:底部操作条按钮改常规尺寸(ghost/primary),页头图标按钮统一 ghost icon-only;抽屉内紧凑场景才用 sm
4. **「我的清单」并入「自动下载」**:清单即自动下载名单(逻辑本就重合),页头分段改为 关注动态/自动下载/关注列表;清单管理仍在抽屉
5. **侧边栏极简**:底部只留登录状态一项;设置表单与主题选择整体并入「账号」抽屉(打开时 loadConfigIntoUI 填充)
6. 保留勾选+底部操作条的批量下载能力(用户既有工作流),仅下载记录页隐藏勾选
