# bilibili download — 需求文档

> 按用户原话整理的需求点(按时间顺序),每条标注验收标准。文末是验收测试结果。

## 一、项目起源与核心诉求

### R0 核心定位
- **用户**:B 站大会员用户,想**把视频高画质地留存到本地**自用
- **形态**(经用户确认):**本地网页应用**(Python Flask 后端 + 浏览器界面),不是油猴脚本,不是 Electron
- **核心流程**:粘贴 B 站视频地址 → 选清晰度 → 稳定下载到本地,支持大会员专属画质(1080P+/4K)

### R1 三种登录方式(用户确认)
> 用户原话:"我有哔哩哔哩大会员,我会给予你登陆账号"

| 方式 | 说明 |
|---|---|
| ① **扫码登录**(主) | 网页显示二维码,手机 B 站 App 扫码,长期有效 |
| ② **使用 Edge** | 读 Edge 已有登录态(用户平时用 Edge 登 B 站) |
| ③ **cookies.txt**(兜底) | 装扩展导出后粘贴 |

**用户明确拒绝**:账号密码+验证码(B 站触发极验滑块,无法无人值守通过)。

### R2 登录态正确识别
> 用户原话:"右上角始终显示未登录","无论我扫码成功还是使用edge成功,你右上角都应该变成已登陆"

- **验收**:任意一种登录成功后,右上角徽章立即变成「✓ 已登录 用户名 [大会员]」,**不能停留在「未登录」**

### R3 登录区 UX
> 用户原话:"登录的这个界面就没了,只需要直接展示让我贴下载视频的链接的地方"

- 登录成功后**整个登录区隐藏**,直接展示下载区
- 右上角加「退出」入口可重新登录

### R4 扫码成功的正确收尾
> 用户原话:"扫描完二维码,上面未登录的那个状态没有变,而且二维码也没有收起来"

- 扫码成功 → **二维码图收起** + 显示「✓ 登录成功!」+ 刷新徽章

## 二、下载能力

### R5 基础下载
- 输入 URL → 解析 → 列出清晰度 → 选 → 下载
- **大会员高画质**:1080P+/4K 必须能下(需带登录态 cookie)
- **DASH 音视频合并**:高画质自动用 ffmpeg 合并成单 mp4

### R6 进度条
> 用户原话:"下载中的可以做一个进度条吗?"

- 下载中显示**进度条 + 百分比 + 速度 + 剩余时间**
- 修复过一次:**status 不切换**导致进度条不显示的 bug

### R7 多 P 分集视频
> 用户原话("优化"时提到,后被纳入)

- 多 P 视频自动识别 → 选单集或批量多选

### R8 批量下载(三种)
> 用户原话:"我该怎么触发批量下载?"

- ① **多链接一次下**:每行一个 URL
- ② **分P选集下**:勾选要下的 P
- ③ **收藏夹/合集下**:输入收藏夹或合集链接

## 三、内容浏览(用户的重点需求)

> 用户原话:"做一个我的b站观看历史,还有我的b站关注up列表,或者我配置一个关注up清单,给我一个按钮,我每天点击一下就能刷新他有没有新增的视频,这样我就不用去复制链接过来解析,而是直接在你这看到一些视频...直接多选视频进行下载"

### R9 观看历史(A1)
- 拉观看历史,自动加载,带封面+标题+UP+时长+**观看进度百分比**
- 多选下载

### R10 关注更新(A2)
- 拉关注 UP 主最新投稿,合并按时间倒序
- 多选下载

### R11 自定义 UP 清单 + 一键刷新看新增(A3,用户最想要)
- 维护一个 UP 主清单(主页链接或 mid)
- 点「刷新看新增」→ 只显示**自上次以来的新增视频**
- 多选下载

### R12 收藏夹浏览(A4)
- 列出所有收藏夹 → 点进看内容 → 多选下载

### R13 稍后再看(A5)
- 直接展示「稍后再看」,多选下载

### R13a 内容浏览的关键体验
> 用户原话:"列表左边我没办法看到视频封面,这样我没办法预览"
- **封面必须能显示**(B 站 CDN 反盗链 → no-referrer 修复)
- **打开页面自动刷新历史**(用户原话)
- **列表搜索过滤**(标题/UP 主,实时)

## 四、下载管理与设置

### R14 队列管理
> 用户原话:"下面下载队列这里,我想要有单选/多选删除的按钮,然后点击删除时让我选择只是删除下载记录还是记录和文件都删除。然后再有一个清除所有记录的按钮"

- 单选/多选删除,**删除时二选一**:仅删记录 / 删记录+文件
- 「清除所有记录」按钮

### R15 下载失败自动重试(B1)
- 网络抖动自动重试 2 次(共 3 次),用户取消不重试

### R16 下载设置:并发数/限速(B2)
- 界面可配同时下载数(1-4)、单任务限速,持久化

### R17 下载目录界面可选(B3)
> 用户原话("优化"提到)
- 界面上改下载目录,不用改 config.py

### R18 下载完成打开文件(R1 扩展)
- 完成后「在 Finder 中显示」按钮

## 五、视觉与设置

### R19 深色模式(C1)
- 浅色/深色/跟随系统,持久化

### R20 网格/列表切换(C2)
- 视频卡片网格(像 B 站)或列表,持久化

### R21 统计面板(C3)
- 顶部条:总下载数、总大小、本月、今日

### R22 未做项(B6 后台托盘)
- 经评估**不做**(BACKLOG 有详细理由),用户接受了

## 六、最近几次的修复

### R23 关注/UP清单/收藏夹 tab 不卡 spinner
> 用户原话:"切到关注/UP清单/收藏夹 tab"会"加载中卡很久"
- 后端:缓存延长 5 分钟,加 ?force=true
- 前端:有缓存数据时立即渲染,后台拉新

### R24「加载中」一致显示
> 用户原话:"他仍然会一直展示'加载中',不应该这样"
- **根因**:HTML 嵌套错误导致重复 placeholder 一直可见
- **修复**:删掉重复块 + 唯一 ID + 容器默认 display:none

## 关于"内容为空"的说明

测试中发现以下接口返回 0 条,**不是 bug**,是用户账号本身的状态:
- `/api/fav-content`:返回 0(收藏夹设为私密,API 内容不可见)
- `/api/watchlater`:返回 0(用户没有稍后再看的视频)
- `/api/up-updates`:部分 UP 返回 0(B 站对 arc/search 限流,等几分钟恢复)

这些接口本身工作正常,数据有内容时会正常显示。
